# v2.5 API expansion — phased roadmap & reference catalog

**Status:** living document with a phased implementation order.  
**Goal:** turn Situation API gaps into reviewable phases so **examples, small games, and Quest/NRC consumers stay thin**, with **concrete C signatures** and implementation checklists to anchor development.  
**Constraint:** shipping items should target **OpenGL + Vulkan parity** unless explicitly tagged `[GL only]` / `[VK only]`.

**Related:** `doc/plan/LIBRARY_BUGFIX_PLAN.md`, `sit/situation_api.h`, Quest Spectral Renderer / NRC Task 3.4 readback needs.

---

## How to use this file

1. Execute the **phase roadmap** in order unless a maintainer explicitly reprioritizes a phase.  
2. Use the lettered sections as the **reference catalog** for API signatures, backend notes, and scars.  
3. Add findings under the right reference section; keep **one idea per row** in tables when possible.  
4. Signatures below are **proposals** — names, parameter order, and enum shapes may change after review.  
5. Tag **`[GL+VK]`** when both backends must behave the same; note hazards (Y-flip, NDC, clip control).  
6. When an item graduates to implementation, link the PR/issue here and trim or move detail to `doc/situation_api.md`.

---

## Conventions (proposed)

- Returns **`SituationError`** for create/update/bind failures; void for trivial release.  
- **`SituationCommandBuffer cmd`** for anything that must be **recorded** and replayed in order with draws.  
- Immediate **`SituationSetShaderUniform*`** remains for GL-style global program uniforms; Vulkan path may map to push/descriptor updates internally.  
- New small enums live next to similar types in `situation_api.h` (names below are illustrative).

## Phase roadmap

This roadmap is the execution order for v2.5 API expansion work. A phase should leave the tree in a shippable state: public declarations, both backend paths or an explicit backend tag, tests/examples where appropriate, and documentation updated.

### Phase 0 — Scope lock and API shape

**Purpose:** prevent signature churn and backend ambiguity before code lands.

- [x] Confirm whether new create functions follow the current `SituationError ...(..., out_handle)` style or the older direct-return stub style.
- [x] Confirm which APIs are required for v2.5 shipping versus parked for future releases.
- [x] Confirm `[GL+VK]` parity expectations for every phase item.
- [x] Define error behavior for void functions that can receive invalid handles.
- [x] Define whether per-frame GPU completion is guaranteed by `SituationEndFrame` / next `SituationAcquireFrameCommandBuffer`, or whether a narrower per-feature fence rule is needed.
- [x] Add an implementation issue/PR checklist that links back to this document.

**Exit criteria:** phase owners can implement without inventing signatures, error semantics, or synchronization contracts mid-task.

### Phase 1 — Quest/NRC async buffer readback

**Purpose:** unblock NRC Task 3.4 with a tiny, non-stalling GPU→CPU telemetry path.

**Reference sections:** **K**, **N**

- [x] Ship `SituationCreateReadbackBuffer`.
- [x] Ship `SituationCmdCopyBuffer`.
- [x] Ship `SituationReadBuffer`.
- [x] Prove frame-boundary readback safety on OpenGL and Vulkan.
- [x] Dogfood the API in the Quest/NRC adaptive training path.
- [x] Add GL+VK regression tests for create/destroy, offset copy, next-frame counter read, first-frame behavior, bounds, and no-stall reads.

**Exit criteria:** Quest/NRC can read the previous frame's 4-byte atomic counter without blocking the CPU or branching on GL/VK.

### Phase 2 — Diagnostic readbacks and visibility tools

**Purpose:** make backend bugs observable without private struct peeking or screenshot-file roundtrips.

**Reference sections:** **D.2**, **D.3**, **G.1**, **J**, **M**

- [x] Add blocking `SituationReadTexture` / optional `SituationReadTextureAlloc` for tests and asset verification.
- [x] Add `SituationGetTextureInfo` and sampler inspection/control needed by K-Term atlas diagnostics.
- [x] Add `SituationReadFramebuffer` for cropped final-pixel diagnostics.
- [x] Decide whether `SituationRunShaderProbe` belongs in the SDK or the harness.
- [x] Update K-Term diagnostics to prove CPU cell data, uploaded atlas bytes, shader output, and final presentation pixels.

**Exit criteria:** K-Term display bugs can be classified as CPU data, upload, shader, or presentation failures using public APIs.

### Phase 3 — Low-risk developer ergonomics

**Purpose:** reduce example duplication and silent failure before larger rendering changes.

**Reference sections:** **C.1**, **C.2**, **H**, **I**

- [x] Add uniform array/matrix upload helpers.
- [x] Add shader uniform validation helpers for development builds.
- [x] Add logging callback/message-box improvements for Windows subsystem builds.
- [x] Add `SituationGetGraphicsCaps` so examples stop scattering backend/compiler checks.

**Exit criteria:** examples and small consumers can detect missing capabilities and uniform mistakes without backend-specific code or hidden stderr.

### Phase 4 — Recorded render-state correctness

**Purpose:** make command-buffer rendering deterministic when user draws mix with internal passes.

**Reference sections:** **B**, **C.3**, **J**

- [x] Add recorded cull/depth/blend state commands.
- [x] Decide whether push/pop raster state is required for internal pass bracketing.
- [x] Align push/root constant API shape with existing command recording.
- [x] Add debug groups if RenderDoc/PIX workflow needs them during this phase.


**Exit criteria:** examples can mix `CmdDrawMesh`, `CmdDrawQuad`, compute, and internal rendering without relying on hidden default GL/VK state.

### Phase 5 — Unified Camera and Projection Pipeline

**Purpose:** remove repeated math, enforce a single NDC/depth convention, and formalize projection state across backends.

**Reference sections:** **A**, **E**, **F**, **L**

- [x] Define `SituationCameraDesc` with standard parameters (eye, target, up, fov, clipping planes, aspect).
- [x] Add `situation_impl_proj.h` subsystem for building view, projection, and inverse matrices via `cglm`.
- [x] Add unprojection helpers (`SituationCameraUnprojectPixel`) for accurate screen-to-world raycasting.
- [x] Document strict NDC and depth range conventions (`CGLM_FORCE_DEPTH_ZERO_TO_ONE` on Vulkan).

**Exit criteria:** `fps_ray_demo`-class examples lose duplicated camera math, projection errors are eliminated, and screen picking is universally accurate without backend-specific hacks.

### Phase 6 — Larger offscreen/render-target design

**Purpose:** tackle the broader render-target API only after smaller state/readback contracts are stable.

**Reference sections:** **G**, **K.13**, **P**

- [ ] Design `SituationRenderTarget` ownership, color/depth formats, MSAA, load/store behavior, and texture resolve rules.
- [ ] Decide if texture/image debug dumps need `SituationCmdCopyBufferToImage` or a separate image readback family.
- [ ] Decide if explicit fences are public API or remain backend internals.
- [ ] Revisit mapped-pointer exposure and GPU fill commands only if earlier phases show a real performance need.

**Exit criteria:** offscreen rendering and future GPU readback/fence additions have a coherent design instead of ad hoc helper growth.

**`[GL+VK]`** Requires `TRANSFER_DST` (or equivalent) at creation; document interaction with **sRGB** flag on `SituationCreateTextureEx`.

### D.2 Readback / upload verification `[GL+VK]`

**Pain:** Libraries such as K-Term can validate the CPU-side `SituationImage` handed to `SituationCreateTextureEx()`, but cannot prove that the uploaded GPU texture contains the same bytes. K-Term's font atlas tests need this to turn “font atlas dimensions and byte layout” from a CPU/metadata assertion into a true backend upload assertion.

```c
typedef enum SituationTextureReadFormat {
    SIT_TEXTURE_READ_RGBA8 = 0, /* normalized RGBA bytes, backend-independent */
} SituationTextureReadFormat;

typedef struct SituationTextureReadbackDesc {
    SituationTextureRegion region;       /* mip_level 0 unless explicitly supported */
    SituationTextureReadFormat format;   /* default SIT_TEXTURE_READ_RGBA8 */
    size_t dst_row_pitch_bytes;          /* 0 = tightly packed width * 4 */
} SituationTextureReadbackDesc;

/* Blocking debug/test helper. Reads texture pixels into caller-owned memory. */
SITAPI SituationError SituationReadTexture(
    SituationTexture texture,
    const SituationTextureReadbackDesc* desc, /* NULL = full mip0 RGBA8 */
    void* dst_pixels,
    size_t dst_size_bytes);

/* Optional allocator convenience. Caller frees with SituationFree/SIT_FREE policy. */
SITAPI SituationError SituationReadTextureAlloc(
    SituationTexture texture,
    const SituationTextureReadbackDesc* desc,
    SituationImage* out_image);
```

**`[GL+VK]`** OpenGL can use `glGetTextureImage`/equivalent. Vulkan needs textures created with transfer-source capability or an internal copy-capable fallback path. Document that readback is slow, synchronization-heavy, and intended for tests, diagnostics, screenshots, and asset verification rather than per-frame gameplay.

**K-Term unblock:** once this exists, add a focused assertion that reads `term->font_texture` and byte-compares it with `term->font_atlas_pixels` for dimensions, row pitch, alpha mask, and the padded 8x8 glyph inside the 10x10 terminal-cell contract.

## K. Async buffer readback for Quest/NRC `[GL+VK]`

**Pain:** The Quest Spectral Renderer / NRC adaptive training loop needs to read a tiny GPU-written value every frame without stalling the CPU. The immediate/blocking readback helpers used by tests are too heavy for this path; the desired contract is an async GPU→CPU copy recorded in frame **N**, then a pure CPU read of frame **N-1** data at the start of frame **N+1**.

**Current consumer shape:** an NRC atomic counter buffer is copied into a 4-byte readback buffer after the path tracing dispatch. The next frame reads that count to choose how many training iterations to run. One-frame-stale data is acceptable because sample counts are temporally coherent and camera flush handling resets discontinuities.

### K.1 Quest/NRC API coverage snapshot

The Quest Spectral Renderer already consumes the current compute/render subset heavily. This section is scoped to the missing async buffer readback surface, but the implementation must fit the existing API style instead of creating a separate "NRC-only" path.

| Area | Existing surface consumed today | Status | Quest/NRC relevance |
|------|---------------------------------|--------|---------------------|
| Lifecycle | `SituationInit`, `SituationShutdown`, `SituationGetRenderWidth`, `SituationGetRenderHeight` | Implemented | Initializes the renderer, render resolution, and GPU context. |
| Frame loop | `SituationAcquireFrameCommandBuffer`, `SituationGetMainCommandBuffer`, `SituationEndFrame` | Implemented | Readback safety depends on frame boundary semantics. |
| Buffers | `SituationCreateBuffer`, `SituationDestroyBuffer`, `SituationUpdateBuffer`, `SituationGetBufferDeviceAddress` | Implemented | NRC uses storage buffers and BDA for path tracing/training data. |
| Textures | `SituationCreateTexture`, `SituationCreateTexture3D`, bindless handles, residency, destroy | Implemented | Spectral/path tracing resources and debug views. |
| Compute | `SituationCreateComputePipeline`, bind buffer/texture, dispatch, barrier | Implemented | Path trace, training, inference, and counter accumulation. |
| Rendering | virtual display creation/composition, render pass begin/end | Implemented | Quest-facing compositing and debug visualization. |
| Async buffer readback | `SituationCreateReadbackBuffer`, `SituationCmdCopyBuffer`, `SituationReadBuffer` | **Missing** | Required for NRC Task 3.4 adaptive training control. |

### K.2 Required API additions

```c
/* Host-visible staging buffer for GPU->CPU copies. */
SITAPI SituationBuffer SituationCreateReadbackBuffer(size_t size);

/* Record src[offset..offset+size) -> dst[0..size) in the current command stream. */
SITAPI void SituationCmdCopyBuffer(
    SituationCommandBuffer cmd,
    SituationBuffer src,
    SituationBuffer dst,
    size_t offset,
    size_t size);

/* CPU-side memcpy from a completed readback buffer into caller-owned memory. */
SITAPI void SituationReadBuffer(
    SituationBuffer readback_buf,
    void* dst,
    size_t size);
```

`SituationDestroyBuffer(&buf)` should destroy readback buffers too; if the implementation stores a mapped pointer alongside the existing `SituationBuffer` id/size pair, the public handle can stay unchanged.

### K.3 Functional requirements

| ID | Requirement | Rationale | Acceptance check |
|----|-------------|-----------|------------------|
| K-R1 | Create a host-visible readback buffer with `SituationCreateReadbackBuffer(size)`. | NRC needs a persistent 4-byte counter destination, and future tools may read larger telemetry blocks. | Creating `sizeof(uint32_t)` and larger buffers succeeds on GL and VK. |
| K-R2 | The readback buffer is persistently mapped, or can be read with no per-frame mapping cost. | The per-frame path must not allocate, map, or stall. | `SituationReadBuffer` does not call GL/VK queue wait APIs or allocate temporary staging. |
| K-R3 | The CPU never writes readback buffers through this API. | Keeps the resource role simple and avoids cache/coherency ambiguity. | `SituationUpdateBuffer` on readback buffers is rejected or documented as invalid. |
| K-R4 | `SituationCmdCopyBuffer` records `src[offset..offset+size)` to `dst[0..size)`. | The NRC counter can live inside a larger SSBO. | Test copies a non-zero offset from a storage buffer and reads the expected bytes next frame. |
| K-R5 | Copy ordering follows the recorded command stream and explicit barriers. | Counter reads must observe completed path tracing writes. | Dispatch writes counter, barrier, copy, next-frame read sees dispatch result. |
| K-R6 | `SituationReadBuffer` is CPU-only after synchronization is satisfied. | This is the core no-stall contract. | Code inspection/test instrumentation verifies no GPU command submission or wait in the read call. |
| K-R7 | Destroy path unmaps/frees readback buffers through `SituationDestroyBuffer`. | No separate public lifetime model is needed. | Leak checks and repeated create/destroy loops pass. |

### K.4 Contract details

- `SituationCreateReadbackBuffer(size)` allocates a host-visible staging buffer optimized for GPU→CPU readback. It should be persistently mapped, or at least mappable with effectively zero per-read overhead.
- The CPU never writes readback buffers. They are one-way GPU→CPU channels and should not be passed to `SituationUpdateBuffer`.
- `SituationCmdCopyBuffer(cmd, src, dst, offset, size)` records an async copy. `offset` is a byte offset into `src`; `dst` is written at byte offset `0`.
- The copy executes after preceding dispatches/draws that are ordered by the command stream and any required `SituationCmdPipelineBarrier(cmd)`.
- `SituationReadBuffer(readback_buf, dst, size)` is a pure CPU copy from the mapped staging pointer. It must not issue GL/Vulkan commands or wait on the GPU.
- The caller must read in a later frame after the copy is known complete. The standard usage is: copy in frame **N**, read in frame **N+1**.

### K.5 Frame fence requirement

`SituationEndFrame()` must guarantee that all GPU work submitted in the current frame command buffer is complete before the next frame's `SituationAcquireFrameCommandBuffer()` returns, or the readback implementation must provide equivalent per-readback-buffer safety.

This is the foundation of the one-frame-delayed readback pattern. If the renderer uses more than one in-flight frame, the implementation should either:

- keep the public contract to double-buffered submission where frame **N+1** can safely read frame **N** readback data; or
- internally ring-buffer readback staging buffers to match frames-in-flight and document which previous frame is safe to read.

For Vulkan triple buffering, a single readback buffer is not enough unless the acquire/fence pattern really waits for the previous submitted frame. If the backend waits on a frame from two or three submissions ago, readback staging needs the same ring depth or explicit fences. For the v2.5 API, prefer the simpler double-buffer-safe contract unless the renderer already exposes a frames-in-flight model.

| Backend/frame model | Required safety rule | Implementation consequence |
|---------------------|----------------------|----------------------------|
| OpenGL, single command stream | Copy completes before the next acquire-equivalent point exposes readback data. | `glFinish`, swap completion, or a fence inserted after the copy must cover the frame boundary. |
| Vulkan double-buffered frames | Frame N fence is complete before frame N+1 reads the staging buffer. | One readback buffer can satisfy the public sample pattern. |
| Vulkan triple-buffered frames | Frame N+1 may not be safe if only an older fence is waited. | Use an internal staging ring matching frames-in-flight, or expose explicit fences before claiming one-frame safety. |
| Future async transfer queue | Copy queue completion must be joined before read. | Add explicit fence/semaphore handling; do not hide a stall inside `SituationReadBuffer`. |

### K.6 Backend implementation plan

| Step | OpenGL work | Vulkan work | Shared/API work |
|------|-------------|-------------|-----------------|
| K-I1 | Add readback buffer allocation using immutable storage with read/persistent/coherent flags. | Add buffer with `VK_BUFFER_USAGE_TRANSFER_DST_BIT`; allocate host-visible memory, preferably host-cached. | Extend internal buffer slot metadata with `is_readback`, `mapped_ptr`, `mapped_size`, and backend memory handle if needed. |
| K-I2 | Map once with `glMapNamedBufferRange`; store pointer. | `vkMapMemory`/VMA map once; store pointer. | `SituationDestroyBuffer` unmaps/frees correctly for readback buffers. |
| K-I3 | Implement command copy with `glCopyNamedBufferSubData(src, dst, offset, 0, size)`. | Record `vkCmdCopyBuffer` with `{ srcOffset=offset, dstOffset=0, size=size }`. | Validate bounds: `offset + size <= src.size` and `size <= dst.size`. |
| K-I4 | Ensure GL command ordering after compute writes via existing `SituationCmdPipelineBarrier`. | Ensure buffer transfer destination usage and memory barriers make shader writes visible to transfer reads. | Document that callers still issue `SituationCmdPipelineBarrier` after dispatch before copy. |
| K-I5 | If swap/present does not guarantee completion, insert and wait a GL sync at the frame boundary. | Tie readback safety to the frame fence for the submitted command buffer, or ring staging internally. | Do not add waits inside `SituationReadBuffer`. |
| K-I6 | `memcpy` from coherent mapped pointer. | Invalidate non-coherent mapped ranges, then `memcpy`. | Keep `SituationReadBuffer` CPU-side and deterministic. |

OpenGL:

```c
GLuint buf;
glCreateBuffers(1, &buf);
glNamedBufferStorage(buf, size, NULL,
    GL_MAP_READ_BIT | GL_MAP_PERSISTENT_BIT | GL_MAP_COHERENT_BIT);
void* mapped = glMapNamedBufferRange(buf, 0, size,
    GL_MAP_READ_BIT | GL_MAP_PERSISTENT_BIT | GL_MAP_COHERENT_BIT);

glCopyNamedBufferSubData(src.gl_id, dst.gl_id, offset, 0, size);
memcpy(dst_cpu, readback_buf.mapped_ptr, size);
```

The copy is ordered in the GL command stream and should not block the CPU. If `SwapBuffers` does not imply enough completion on the active driver/present mode, insert a fence after the copy and wait before the next frame acquire path that exposes the data to `SituationReadBuffer`.

Vulkan:

```c
VkBufferCreateInfo ci = {
    .size = size,
    .usage = VK_BUFFER_USAGE_TRANSFER_DST_BIT,
};
/* Allocate HOST_VISIBLE, preferably HOST_CACHED; map once and store pointer. */

VkBufferCopy region = {
    .srcOffset = offset,
    .dstOffset = 0,
    .size = size,
};
vkCmdCopyBuffer(cmd, src.vk_buf, dst.vk_buf, 1, &region);
/* If memory is not HOST_COHERENT, invalidate before memcpy. */
memcpy(dst_cpu, readback_buf.mapped_ptr, size);
```

Host-cached memory is preferred for CPU reads. If the chosen Vulkan memory type is not host-coherent, `SituationReadBuffer` may still remain "zero GPU interaction", but it must call `vkInvalidateMappedMemoryRanges` before the CPU `memcpy`.

### K.7 Quest/NRC use-case impact

| Use case | Current limitation | New behavior after K ships | Notes |
|----------|--------------------|----------------------------|-------|
| NRC adaptive training | Training iteration count cannot react to the previous path trace sample count without a blocking read. | Frame N reads frame N-1 counter with a CPU `memcpy`, then schedules frame N copy after tracing. | Primary Task 3.4 requirement. |
| Quest frame pacing | CPU should not stall on GPU telemetry during a headset frame. | Readback moves synchronization to the existing frame boundary. | Important for VR latency; no hidden wait in `SituationReadBuffer`. |
| Camera discontinuity handling | Counter values can be stale around camera resets. | One-frame staleness remains acceptable because camera flush logic resets accumulation. | Document as caller responsibility. |
| GPU diagnostics | Existing texture/framebuffer readbacks are blocking and test-oriented. | Tiny per-frame counters use a lightweight staging path. | Keep debug image dumps as a future extension, not part of this critical path. |
| Backend portability | GL and VK synchronization semantics differ. | Public API describes a single frame-boundary contract and backend-specific obligations. | Prevents Quest/NRC from growing backend branches. |

### K.8 NRC adaptive training usage

```c
/* Init */
SituationBuffer readback = SituationCreateReadbackBuffer(sizeof(uint32_t));

/* Frame N pre-trace: read frame N-1 data. */
uint32_t prev_count = 0;
SituationReadBuffer(readback, &prev_count, sizeof(uint32_t));

/* ... choose adaptive NRC training iterations from prev_count ... */

/* Frame N post-trace: after path tracing dispatch + barrier. */
SituationCmdCopyBuffer(cmd, atomic_counter_buf, readback, 0, sizeof(uint32_t));

/* EndFrame submits and fences the copy for the next frame's read. */
SituationEndFrame();
```

Timeline:

```text
Frame 0: copy counter -> readback       (no useful read yet)
Frame 1: read frame 0 counter -> copy frame 1 counter
Frame 2: read frame 1 counter -> copy frame 2 counter
```

### K.10 Implementation guardrails

| Do not do in Task 3.4 | Why |
|-----------------------|-----|
| Do not route `SituationReadBuffer` through `SituationGetBufferData` or `_SituationVulkanReadBackBuffer`. | Those paths are synchronous diagnostics and can stall Quest frame pacing. |
| Do not add texture/image readback to this implementation pass. | NRC Task 3.4 only needs a 4-byte buffer counter; image readback is future debug scope. |
| Do not hide frame synchronization inside `SituationReadBuffer`. | The API contract relies on frame-boundary completion; hidden waits would make performance unpredictable. |
| Do not require Quest/NRC code to know the backend frame index. | The SDK should preserve backend neutrality. |
| Do not allocate/free staging memory per frame. | The point of the API is persistent low-overhead telemetry readback. |
